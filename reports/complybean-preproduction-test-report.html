Primary performance finding

compliance-mark.png is a 1.27 MB, 1536×1024 PNG that is displayed around 144 px in the homepage visual.

Lighthouse estimates roughly 1.2 MB of avoidable transfer. Convert it to WebP/AVIF and provide appropriately sized variants; do not preload the full-resolution source unnecessarily.

Additional observations

  • Total observed mobile page transfer: 1.867 MiB.
  • Estimated unused JavaScript: 172 KiB (mostly shared Next.js runtime bundles).
  • CSS: about 44.7 KiB; no unused-CSS opportunity was reported.
  • Mobile LCP element was the hero H1; simulated render delay dominated the metric.

ComplyBeanRecommendations and evidence

Prioritized remediation plan

1

Correct page-level canonical metadata

Give every route its own canonical URL. The current site tells search engines that all pages are duplicates of the homepage.

2

Add robots.txt and sitemap.xml

Publish the public route inventory and submit the sitemap in Google Search Console/Bing Webmaster Tools.

3

Optimize the ComplyBean mark

Export appropriately sized WebP/AVIF variants, update the displayed logo references, and retest mobile LCP. This is the highest-value performance improvement.

4

Complete social and structured metadata

Set each page's Open Graph/Twitter title, description, and sharing image; add Organization/WebSite JSON-LD if appropriate.

5

Add automated browser smoke tests to CI

At minimum, assert route availability, no overflow, no broken images, skip-link focus, and mobile menu behavior on every deployment.

6

Optional production hardening

Consider uptime monitoring, error tracking, analytics consent strategy, and a custom-header capable edge layer if CSP and additional security headers are required.
